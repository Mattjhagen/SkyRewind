## DONE — SkyRewind bridge (backend)

### 12. Root causes found, one by one (18:27–18:32 CDT)
1. **dump1090 held the dongle** — manual `rtl_adsb` as `matt`:
   `usb_claim_interface error -6` (device busy). dump1090 PID 42099,
   8.4% CPU. Fixed by `systemctl stop + disable dump1090-mutability`.
2. **Service user lacked USB permission** — `skyrewind` had NO
   `plugdev`; `sudo -u skyrewind rtl_adsb` → `usb_open error -3`.
   Fixed by `usermod -a -G plugdev skyrewind`.
   (Also: bridge had `stderr=DEVNULL`, hiding both errors for hours.)
3. **Output dir owned by dump1090** — bridge:
   `ERROR writing aircraft.json: [Errno 13] Permission denied`
   (`/var/run/dump1090-mutability/aircraft.json.tmp`).
   Fixed by `chown -R skyrewind:skyrewind` + `chmod 775`.
   (Note: `/var/run` is tmpfs — resets on reboot. Permanent fix via
   tmpfiles, see #13.)
4. **CPR bug** — bridge called
   `pms.adsb.position(hex_msg, hex_msg, time.time(), time.time(), …)` —
   same message twice, same timestamp twice. pyModeS `position()`
   needs TWO DIFFERENT messages + TWO timestamps. Bridge also stored
   only CPR lat/lon numbers, never the hex strings, so a pair could
   never be built. Fix: store even/odd hex + timestamps, global
   `position()` first, `position_with_ref()` fallback, sanity check
   within 10° of receiver.
